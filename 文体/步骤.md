# 写步骤 · 照着做不用猜

起因(2026-10-06):让一个没有背景的子代理冷读两份真实的 HANDOFF,只读不做,逐步标「能直接做 / 要猜 / 卡住」。
23 步里 11 步要猜、4 步卡住。卡点几乎都能对上航空维修手册的受控英语 ASD-STE100 写步骤那几条,
和 DITA 把「步骤」跟「背景」分开写的做法。下面是那几条,用这次卡住的原句当例子。

先读核心规范 [规范.md](../规范.md)(用词、能愿动词等所有文体共用的部分),下面只写步骤类多出来的规矩。

## 下笔时

- **一步一个动作。** 一个编号只放一个要做的事;几个动作必须同时做才合在一起。
- **条件写在动作前面。** 「端口那行是空的,就后台启动 Blender:」再给命令。别把「(后台跑,约 10 秒后重查端口)」挂在命令后面,读者会先照着命令前台跑了。
- **命令能原样复制运行。** 要后台跑,命令里就带 `&`,或写明「会占住终端约 5 分钟」;不留 `<你的 CLAUDE.md 或 rules/common 拼接>` 这种要读者自己补的占位符,真要读者填的,写清填什么、从哪拿。
- **每步写怎么算做完。** 跑完看到什么、期望值是多少、不对时去哪一步。期望值过时了就改掉,别让「期望 58 tests, 57 pass」和下面的「57 无网单测」并存。
- **警告放在相关步骤前面,先说做什么再说为什么。** 「别手改 GLB,坏了就重跑第 3 到 7 步 —— 手改的会被下次导出覆盖。」不埋在段落中间。
- **同一个东西从头到尾一个叫法。** 前面叫「通路 B」后面叫「裸 socket」,读者会以为是两样东西。代号、缩写第一次出现就说清是什么。
- **步骤和背景分开。** 现在要做的步骤放一块;为什么这么做、历史版本、踩过的坑放另一块,步骤里只留指针。划掉的旧步骤挪去历史区,不留在步骤里。
- **要人做的单列。** 充值、选服务商、给 key 这类 agent 做不了的,单独一节「要用户做的」,每条写清做完怎么确认(比如「余额到账:跑 X 返回 200」),步骤里引用它而不是混在编号里。
- **不留改写痕迹。** 「原文写的是 X,实际是 Y」这种话读者看不懂「原文」指哪份,直接写对的那个;要留证据就放历史区。
