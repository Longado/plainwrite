# DITA 主题类型

## 是什么

DITA(Darwin Information Typing Architecture)是 OASIS 维护的技术文档结构标准。核心想法是按信息类型分开写：概念、步骤、参考资料各是一种主题，结构要求不同，不混写。

## 来源和可信度

DITA 1.3 规范：https://docs.oasis-open.org/dita/dita/v1.3/os/part2-tech-content/dita-v1.3-os-part2-tech-content.html ，已读原文，下面是转述。另一个常被提到的 Information Mapping 方法，这次没有查。

## 要点(转述)

- **概念(concept)**：解释是什么、为什么，正文由段落、列表、表格组成。
- **步骤(task)**：照着做的东西。严格形式要求有步骤列表；前提条件、背景、结果、后续、示例可选。
- **参考(reference)**：供查找的资料，比如属性表、语法说明。

## plainwrite 怎么用

| 条目 | 状态 | 在哪 |
|---|---|---|
| 按文体分开写，一种文体一套规矩 | 已收 | `文体/` 里的五份文件就是这么分的：步骤、报告说明、规则、回复、改稿 |
| 步骤和背景分开 | 已收 | `文体/步骤.md`「步骤和背景分开」。冷读实测，背景和步骤混在一起是卡住的主要原因之一 |
| 步骤要写结果 | 已收 | `文体/步骤.md`「每步写怎么算做完」 |
| XML 标记、主题地图等工具层的东西 | 不收 | 我们写的是 Markdown，用不上 |
