# 样例:按规范改写前后

两组真实文件,原文和改写稿成对放(`-原文.md` / `-改写.md`)。改写都是子代理照对应的文体规范做的(当时规范还是 skill 形式,带试读环节),每份改完找了一个没背景的读者试读。读者不认识作者自己的项目名,「看不懂」的数偏高。

另外还试过两份报告和一份接力文件,含客户信息或本机路径,没放进仓库,只在下面写了试读结果。

## 回复：水墨阶段成果

照的规矩：先删再翻译，只留做了什么、往哪改、结论三段；代号翻成白话或删掉；不用加粗当小标题。

**原文（节选）**

> **做了什么**
> - **配方族**：高远、深远、平远各配「石质」和「土质」两种，共 6 个配方……
> - **留白旋钮**：`comp.yoff`，默认 0，旧结果不变。平远取 0、-0.12、-0.24 时，顶部纸面占比量出来是 0.47、0.67、0.79，单调。
> - **复现闸**：`test_repro.py` 仍通过，三种默认配方与 v2 逐像素 0 差。
> ……
> - 之前预登记的 R1 到 R3 没有对新配方重测……

**改写后（全文）**

> 阶段成果 3 做完了：高远、深远、平远各配石质和土质两种，共 6 个配方，都能出图；另加了一个控制山体上方留白的旋钮，默认不变，旧结果不受影响。哪张像水墨、好不好，没有外部判据，只是我目测。
>
> 目测下来，石质和土质一眼能分开，深远和高远成立；平远有层次，但还偏剪纸叠层，层间缺云气过渡。留白拉到最大（-0.24）时山体几乎被挤出画面，不可用，大约在 -0.12 到 0 之间可用。
>
> 没做完的有两处。之前登记好的三项检查没对新配方重测，所以「配方族是否满足三远规则」没有结论。平远石质的台地山脊出现方块台阶，我改回了默认山脊，等于绕开，台地本身没解决。
>
> 下一步我打算给 6 个配方重跑那三项检查，再修苔点和光晕。你没有必须做的事；想的话告诉我 6 张里哪张最不像水墨，我往那边调。

试读：864 字压到 411 字；看不懂的地方从 11 处降到 7 处。

## 规则：testing.md

照的规矩：GB/T 1.1 能愿动词（应 / 宜 / 可），文件开头放一句图例；触发条件写在前面。看不出你想要多硬的规则，标「强度待作者定」。

**原文**

> For new non-trivial logic:
> - RED-GREEN-REFACTOR cycle: failing test → minimal code to pass → refactor
> - Iron Law: no production code without a failing test first
> - Don't reuse the same value in test and implementation

**改写后**

> 本文件的义务词照 GB/T 1.1-2020：「应 / 不应」= 必须做到，任何情况都不能违反；「宜 / 不宜」= 默认这样做，有理由可以不做，但要说出理由；「可 / 不必」= 做不做都行。
>
> 针对新写的非平凡逻辑：
> - 宜走 RED-GREEN-REFACTOR 循环：先写失败的测试，再写刚好能通过的代码，最后重构〔强度待作者定〕。
> - 写生产代码之前，宜先有一个失败的测试（原文称 Iron Law）〔强度待作者定〕。
> - 测试与实现里不宜用同一个值（有假绿风险）〔强度待作者定〕。

试读：原文 40 条规则里，读者按两种读法判出的硬度有 9 条对不上；加了图例的改写稿 20 条全部一致。但有 15 条「待作者定」，这些要作者来定。

## 步骤：一份 3D 建模项目的接力文件（没放进仓库）

照的规矩：一步一个动作；条件写在动作前面；每步写怎么算做完；警告放在命令前；要你做的单列一节。

**原文**

> ```
> /Applications/Blender.app/Contents/MacOS/Blender --python ".../startup.py"
> ```
> （后台跑，约 10 秒后重查端口。）

**改写后**

> 3. **只有端口那行为空时才做**（说明 Blender 被关了；这是唯一允许自行修复的一项）。后台启动 Blender，命令带 `&`，启动后立刻返回：……

试读：只照规则改一遍，读者要猜的步数反而变多；按冷读结果再改一轮才降下来。两个读者分别是 18 步要猜 6、16 步要猜 4，原文两个读者是 12 步要猜 4、13 步要猜 7。改写时还查出原文两处事实写错了。
